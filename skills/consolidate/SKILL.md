# Consolidate

Reduce duplicated skills without losing useful behavior. Compare intended results
and quality requirements, not just names or similar prose. Discuss in the user's language.

## 1. Compare the supplied skills

Inspect the skills or skill directory the user identifies. Use names and descriptions
to find candidates, then read their instructions, linked resources, evaluation
criteria, and available accepted examples. Identify differences in outcomes, inputs,
templates, constraints, permissions, and required tools or environments.

Group skills only when one coherent skill can serve their purposes more clearly.
Represent incidental input or template differences as inputs/resources when suitable.
Keep distinct purposes separate, especially when merging requires many branches,
conflicting rules, or incompatible dependencies. If no merge helps, report that.

## 2. Confirm the consolidation plan

Show each proposed source-to-target mapping, the target name and one-line purpose,
essential behavior to preserve, and what will remain separate or be retired.
Explain meaningful differences and ask the user to resolve conflicting requirements;
do not silently discard one source's constraints or broaden its permissions.
Account for existing target folders and known callers before proposing replacement.

**Wait for confirmation of the concrete plan before consolidating.** Reconfirm
material revisions to the grouping, outcome, retained requirements, or retirement
plan. Confirmation already given for the current plan remains valid; silence is not
approval. Limit changes to the confirmed skills and mappings.

## 3. Build the minimal replacement

Keep restorable originals and stage replacements outside active skill discovery.
Extract the shared essentials; review deletion, merging/shortening, and revision
before adding anything. Do not concatenate source
instructions or turn a successful exception into a universal rule.

Preserve necessary source-specific capabilities through concise input handling or
templates. Keep only needed resources and code, with relative references and clear
dependencies. Choose tools and languages for the task. Do not move excess text into
references or introduce a mandatory chain of other skills to hide complexity.
Carry meaningful source checks and their invocation into the replacement; instruct
it to run them before delivery, report failed or untested criteria, and present
concrete review questions only for judgments code cannot establish.
If the merge becomes less coherent than the originals, revise the plan with the user.

## 4. Verify retained capabilities

Check metadata, resource links, and known callers. Reuse the sources' meaningful
checks and representative accepted examples from each source, including differences
the merge could erase. Compare the candidate with the relevant source under comparable
conditions; use an unseen input when feasible. Keep acceptance criteria fixed and
verify final artifacts or state, not just the agent's completion claim.

Choose verification proportional to the changes. Code checks cover objective
criteria; give the user specific questions for remaining human judgments. A format
pass or shorter combined file alone does not demonstrate capability preservation.
If a necessary check or judgment remains unresolved, leave the originals active
and present the staged candidate with the specific gap.

## 5. Replace the confirmed sources

After required verification and human judgments, apply only the confirmed mapping.
Preserve intervening and unrelated edits. Update known references and remove approved
sources from active discovery, keeping their recovery copies or history outside it.

Report the final mapping, what was preserved, verification results, and recovery
location. Finish without another routine approval gate.
