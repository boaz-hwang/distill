# distill

방금 수행한 업무를 skill 로 남기세요.

[English](README.md) · [스킬 본문](SKILL.md) · [MIT 라이선스](LICENSE)

평소처럼 에이전트와 업무를 진행하세요. 한 번에 끝내도 되고, 여러 번 고쳐도
됩니다. **사용자가 결과에 만족하고 완료를 판단한 시점**에 같은 세션에서
`distill`을 호출합니다.

## 동작

1. **이름과 결과물 확인:** 이름 후보 3개 중 하나를 추천하고, 결과물 한 줄
   설명을 제안합니다. 의도와 다르면 설명을 받아 다시 확인합니다.
2. **핵심 과정 확인:** 필요한 단계를 가능한 적게, 한 줄씩 제안합니다.
   필수 입력·템플릿과 코드/사람 평가의 구분도 함께 드러냅니다.
   수정을 요청하면 반영한 과정을 다시 확인합니다.
3. **스킬 완성:** 확인한 각 단계에 품질을 좌우하는 최소 가이드만 적습니다.
   필요한 템플릿·참조 자료·스크립트를 함께 담습니다.
4. **평가와 개선:** 객관적으로 검증할 수 있는 기준은 재사용 코드로,
   나머지는 짧고 구체적인 사람 평가 질문으로 남깁니다.

두 확인 단계에서는 실제 사용자 응답을 기다립니다. 핵심 과정이 승인되면
추가 승인 단계를 만들지 않고 완성합니다. 이미 사용자가 정한 이름은 존중합니다.

## 무엇을 남기는가

기준은 최종 결과물과 사용자가 그것을 받아들이게 된 피드백입니다.
실패한 경로와 불필요한 탐색은 절차에서 뺍니다. 수정 과정에서 밝혀진 필수
조건은 남깁니다. 그날 사용한 파일명·숫자·도구를 보편 규칙으로 만들지 않습니다.

각 지침에는 한 가지 질문을 적용합니다.

> 이것을 빼면 유능한 에이전트가 사용자가 받아들인 품질 조건을 놓칠 수 있는가?

아니면 삭제합니다. 필요한 내용은 길이가 조금 늘어도 남깁니다.
본문만 줄이고 같은 내용을 참조 파일에 쌓아두지 않습니다.
특정 모델명을 고정하지 않고, 구현 방법을 스스로 선택할 수 있는 모델을 전제로 합니다.

## 설치와 사용

이 저장소 전체가 [Agent Skills 표준](https://agentskills.io/specification)을
따르는 하나의 스킬 폴더입니다. 사용하는 에이전트가 스킬을 읽는 위치에서:

```sh
git clone https://github.com/boaz-hwang/distill.git distill
```

클라이언트에 따라 스킬 목록을 새로고침하거나 세션을 다시 열어야 할 수 있습니다.
작업이 끝난 세션에서 클라이언트의 스킬 호출 기능으로 `distill`을 선택하세요.

> 이 결과면 됐어. distill로 이 세션을 재사용 가능한 스킬로 만들어줘.

관련 대화와 최종 결과물에 접근할 수 있어야 합니다. 기록이 없거나 압축으로
빠진 부분이 있으면, 필요한 근거만 구체적으로 요청합니다.
스킬 본문은 영어이며 사용자와의 대화는 사용자 언어로 진행합니다.

## 평가를 나누는 기준

예를 들어 보고서라면 합계가 원본 데이터와 일치하는지는 코드로 검사할 수
있습니다. 제안이 독자에게 유용한지는 사람이 판단해야 할 수 있습니다.
글자 수 검사를 유용성 평가처럼 취급하지 않습니다.

이런 **업무별 검사 코드는 생성되는 스킬에 포함**합니다. 정상 예시와 일부러
요구 조건을 어긴 예시로 검사 코드가 실제 차이를 잡는지도 확인합니다.
의미 있는 자동 검사가 없다면 억지로 만들지 않고 이유를 밝힙니다.

`distill`에 포함된 도구는 별도로 **스킬 패키지 형식**을 검사합니다.

```sh
uv run /path/to/distill/scripts/validate_skill.py /path/to/generated-skill
```

Python 3.10+와 [uv](https://docs.astral.sh/uv/)가 필요합니다. 첫 실행은 Git과
네트워크로 고정된 버전의 공식 참조 검증기 및 의존성을 가져옵니다.
메타데이터와 포함된 Python 코드의 문법을 검사하며, 대상 코드는 실행하지
않습니다. 통과는 종료 코드 `0`, 실패는 `1`이며 결과는 JSON입니다.
업무 품질은 항상 `not_evaluated`로 구분합니다.

형식 통과만으로 재현성이 확인되지는 않습니다. 생성된 스킬의 실제 실행과
남은 사람 평가가 필요합니다. 향후 피드백은 해당 기준·템플릿·지침·검사 중
필요한 곳만 작게 수정하는 근거로 씁니다.

## 검증과 기여

[영문 개발 안내](README.md#development)의 명령으로 형식 검사와 검증 도구
테스트를 실행할 수 있습니다. CI는 이 자동 검사만 수행합니다.
[행동 평가 시나리오](evals/scenarios.md)는 확인 절차와 결과 품질을 별도로
평가하기 위한 가상 세션입니다. 모델별 동작이 자동 검증됐다는 의미는 아닙니다.

개선 제안에는 실제로 어떤 판단이나 결과가 좋아지는지 보여주세요.
공개 이슈와 예시에 개인 대화나 고객 자료를 올리지 마세요.
